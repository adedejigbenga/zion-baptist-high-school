# Zion Baptist High School

A web application for Zion Baptist High School.

## Purpose

- Public school website
- Student, teacher and admin portals
- Authentication and role-based access
- Student academic records and results management

## Technology Stack

- Next.js (App Router) + TypeScript
- Tailwind CSS
- shadcn/ui
- PostgreSQL (hosted separately) + Prisma ORM
- Zod for validation
- Git for version control
- Deployment target: Vercel

## Current Development Stage

**Step 14 - Public website.** The full public website is built (home, About, Academics, Facilities, Admissions, Student Life, News & Events, Contact, Privacy, Terms) on the existing design system. Images are original illustrations (`public/images/*.svg`, generated by `scripts/generate-illustrations.mjs`) standing in for photographs until the school supplies real ones: see the header of `src/lib/site-images.ts`. Contact details, social links and unconfirmed admissions information are placeholders (`src/lib/site-config.ts`, and the "To be confirmed" badges). The contact form validates but does not deliver messages yet (`src/lib/services/enquiry.ts`).

**Step 13 - Admin portal.** The public site, the portal gateway, a local PostgreSQL database, authentication, the student dashboard and the **student result viewer** (`/portal/student/results`: term selector, printable result sheet, "Result Upload in Progress" for anything unpublished) are built on the design system ([DESIGN-SYSTEM.md](DESIGN-SYSTEM.md), [ARCHITECTURE.md](ARCHITECTURE.md)). The **teacher portal** (`/portal/teacher`: dashboard, My Classes, and result entry at `/portal/teacher/results` with Save Draft and a confirmed Submit; teachers can never publish) and the **admin portal** (`/portal/admin`: directory pages, result review with complete-result checks and confirmed publish/unpublish, announcements, audit logs) are built too. The student profile and announcements pages and admin editing of students, teachers, classes and academic records are not built yet. Hero image, logo mark, news items and contact details are temporary placeholders (see `src/lib/site-config.ts` and `src/lib/demo/`).

## Local Database Setup

PostgreSQL is required for development (version 15 or newer; the project was set up with PostgreSQL 17).

1. **Install PostgreSQL** and make sure the server is running on `localhost:5432`
   (Windows: `winget install PostgreSQL.PostgreSQL.17`, or the installer from postgresql.org).
2. **Create a database and a user** (run as the PostgreSQL superuser, for example with `psql -U postgres`):

   ```sql
   CREATE ROLE zion_app LOGIN PASSWORD 'choose-a-password' CREATEDB;
   CREATE DATABASE zion_baptist_high_school OWNER zion_app;
   ```

   `CREATEDB` lets `prisma migrate dev` create its temporary shadow database.
3. **Configure `.env.local`** (git-ignored; never commit it). Copy `.env.example` and set:

   ```
   DATABASE_URL="postgresql://zion_app:choose-a-password@localhost:5432/zion_baptist_high_school"
   ```

   If the password contains special characters, URL-encode them.
4. **Apply the migrations:** `npm run db:migrate` (runs `prisma migrate dev`).
5. **Load the demo data:** `npm run db:seed` (runs `prisma db seed`). It is safe to run repeatedly.
6. **Reset the development database** (deletes all data, re-applies migrations): `npm run db:reset`, then `npm run db:seed`.
   Only ever do this on a local development database.

Other useful commands: `npx prisma migrate status`, `npx prisma studio`, `npx prisma generate` (after changing the schema).

The first migration (`init_school_portal`) also contains hand-written SQL for rules Prisma cannot express (single current
session/term/default scheme, score and weight checks, grade-band overlap). Keep that SQL if you ever recreate the migration.

### How sign-in works locally

1. Start the database and the app (`npm run dev`), make sure the seed has run (`npm run db:seed`).
2. Open http://localhost:3000/portal and choose the portal that matches the account, or go straight to
   `/portal/student/login`, `/portal/teacher/login` or `/portal/admin/login`.
3. Enter the **Login ID** and the shared demo password. You land on a temporary welcome page for that role
   (all three portals are real).
4. **Log out** with the Logout button in the page header. This revokes the session in the database and removes the cookie.

Good things to try: sign in as a student, then type `/portal/teacher` or `/portal/admin` in the address bar (you are sent
back to your own page); a wrong password shows "Invalid login ID or password."; after Logout, the browser's Back button no
longer shows protected content.

Facts about the implementation: the session is a random token in an HttpOnly cookie (`zbhs_session` locally,
`__Host-zbhs_session` in production); only a hash of it is stored in the `Session` table; students and teachers stay
signed in for up to 7 days (24 hours idle), administrators for 12 hours (2 hours idle); nothing is kept in localStorage.
After 8 wrong attempts for one Login ID within 15 minutes, further attempts for that ID are blocked for the rest of that
window. To clear it while developing, run `DELETE FROM "AuditLog" WHERE action LIKE 'AUTH_%';` against the development
database. Details: [ARCHITECTURE.md](ARCHITECTURE.md), section 4.

## Running the Tests

```bash
npm test            # unit + database tests (vitest)
npm run test:watch  # re-run on change
```

Database tests use a separate `zion_baptist_high_school_test` database. It is created and migrated automatically the
first time (the `zion_app` role needs `CREATEDB`), and the test helpers refuse to run against any database whose name
does not end in `_test`, so the development data is never touched.

## Deployment (Vercel)

- **Live site:** https://zion-baptist-high-school.vercel.app (Vercel project `zion-baptist-high-school`).
- **Commit author matters:** Vercel only accepts deployments whose latest commit is authored by a member of the team. This repo's local git identity is `adedejigbenga <adedejigbenga56@gmail.com>` (the GitHub account's email); a different email gets the deployment "Blocked".
- **Deploy from this machine:** `npx vercel deploy --prod` (you must be signed in to Vercel; check with `npx vercel whoami`).
- **Builds need no database.** Vercel runs `npm install` (which runs `prisma generate` through the `postinstall` script) and `next build`.
- **Sign-in needs a hosted PostgreSQL database.** Until `DATABASE_URL` is set in the Vercel project settings, the live portal shows
  "Sign-in is temporarily unavailable". The database must also have the migrations applied (`prisma migrate deploy`).
- **Search engines are blocked** (robots.txt and a noindex tag) while the site has placeholder content. Set
  `NEXT_PUBLIC_ALLOW_INDEXING=true` in the Vercel settings when the school approves the content.
- **Automatic deploys on push** are not set up yet: the Vercel GitHub app must be authorised for the repository first.
